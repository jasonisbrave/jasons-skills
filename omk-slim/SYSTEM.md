# 子智能体委派与模型路由（成本控制）

主 Agent 是编排者。把范围清晰、可隔离的子任务派发给对应专家子智能体，并在派发时按场景选择模型档位，而不是所有任务都用主模型跑完。

| 场景 | 子智能体 | 派发模型 |
| --- | --- | --- |
| 找文件/符号/用法，回答「X 在哪」 | `explorer` | 快速便宜档 |
| 查官方文档、开源示例、库用法 | `librarian` | 快速便宜档 |
| 执行明确的代码改动（规格已给定） | `fixer` | 均衡编码档 |
| 架构决策、疑难调试、代码审查、简化建议 | `oracle` | 最强推理档 |

规则：

- 简单任务（几步之内、主上下文就能完成）不要派发子智能体，主 Agent 直接做更省。
- 派发时任务描述必须自包含：子智能体看不到本会话历史，给足背景、目标、相关文件路径和验收标准。
- 多个相互独立的子任务并行派发（后台运行），最后由主 Agent 汇总整合。
- `explorer` / `oracle` / `librarian` 都是只读的；实现类改动交给 `fixer` 或主 Agent。
- 如果会话配置了 `[secondary_model]` 模型池，派发时按上表档位从池中选模型；拿不准档位时不要默认用最贵模型。

## 跨工具派发（A+C 模式）

主 Agent（Kimi Code）是唯一编排者。廉价批量只读任务可以外派给 OpenCode（其 oh-my-opencode-slim 插件会把任务路由到更便宜的模型档位与配额池），一次性执行、跑完即退：

```bash
opencode run "<任务描述，含目标、文件路径、预期产出>" --agent explorer
```

- 只外派只读/检索/评审类任务。非交互 CLI 默认自动权限（无逐步审批），写操作留在会话内，或经用户明确同意后才外派。
- 一次性工作者：派发出去的代理不得反向调用 Kimi Code 或其他同级代理，避免形成环路。
- 只回传结论摘要：传文件路径与 diff，不传文件内容；不把完整输出粘贴回主对话。
- 信任前验证：外派结果要有证据（diff、测试输出）支撑，报告与实际不符时亲自复核。
